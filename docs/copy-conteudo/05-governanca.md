# 5. Governança e aceite

Fluxo: proposta → revisão de negócio → implementação → revisão responsiva e acessível → ajustes → aprovação.

Agentes não podem reclassificar pendência como aprovada.

## Checklist

- [ ] problema e resultado antes da ferramenta;
- [ ] um CTA dominante e real;
- [ ] nenhuma promessa não comprovada;
- [ ] datas, preços e disponibilidade vigentes;
- [ ] cases, métricas e depoimentos autorizados;
- [ ] nenhum placeholder em produção;
- [ ] hierarquia semântica preservada;
- [ ] botões descrevem a ação;
- [ ] texto validado no mobile;
- [ ] erros explicam recuperação;
- [ ] metadata corresponde ao conteúdo;
- [ ] termos técnicos contextualizados;
- [ ] grafia N8FLOW revisada.

## Antes do go-live

- [ ] copy aprovada por responsável;
- [ ] primeiro evento completo;
- [ ] oferta da comunidade aprovada;
- [ ] diagnóstico e fluxo comercial definidos;
- [ ] contatos e redes oficiais;
- [ ] políticas legais revisadas;
- [ ] mensagens coerentes com integrações testadas;
- [ ] SEO e OG verificados;
- [ ] módulos condicionais vazios omitidos;
- [ ] revisão final no preview.

Mudanças de posicionamento, promessa, público, oferta ou CTA principal devem ser reconciliadas com PRD/UX e registradas. Alterações pequenas podem seguir por pull request.
